01

一言でいうと

技術に詳しくない方向けに、まず「何ができるアプリか」を。

What

喋ると口が動く

顔を出さずに配信したい人のためのツール。マイクの音に反応してキャラクターの口がパクパク動きます。

How to use

ブラウザで開くだけ

アプリのインストールや会員登録は不要。URLを開いてマイクを許可すれば、その場で使えます。

For

配信・録画で使える

OBSやiPhoneの画面収録と連携。背景を透過・クロマキーにでき、アプリ内で動画録画も可能です。

02

なぜ作ったか

身近な人の「困った」を起点に、既製品ではなく自分で作る道を選びました。

Problem — 課題

顔出しなしで配信したいが、手軽な手段がなかった

知人が配信を始めるにあたり「顔は出したくないが、無言のアイコンでは寂しい」という悩みがありました。

既存のアバターツールは高機能な反面、初期設定が重く、専用ソフトの導入やアカウント登録が前提。もっと軽く、URLひとつで始められるものが欲しい——それが出発点です。

Solution — 解決

「音量にあわせて口を動かす」に機能を絞る

表情認識やカメラは使わず、マイクの音量だけで口パクを成立させる設計に。処理が軽く、スマホでもインストール不要で動きます。

使う人が用意するのは画像1枚だけ。口・目の開閉をまとめた規定フォーマットの1枚シート画像を差し替えれば、すぐ配信に載せられます。

03

仕組み

音声を「口の動き」に変換する信号の流れ。すべてブラウザ内（Web Audio API + Canvas）で完結し、サーバーに音声は送りません。

INPUT マイク入力 getUserMedia 配信/収録の2モード
DSP 音量を平準化 DynamicsCompressor 端末差を吸収
ANALYZE 音量を数値化 AnalyserNode / RMS 実効音量を算出
LOGIC 開閉を判定 threshold + hold 感度・保持時間
RENDER フレーム合成 Canvas + chroma-key 2×2スプライト
OUTPUT 録画・配信 MediaRecorder OBS / 画面収録

※ 口の開閉と目のまばたきを掛け合わせた4フレームを、音量判定にあわせてリアルタイムに切り替えています。

口あき / 目とじ
口とじ / 目あき

04

技術的にこだわった点

「動けばいい」で終わらせず、実際に配信で使える品質まで詰めた部分です。面接でお話しできる具体的な意思決定を挙げます。

◎

端末ごとのマイク差を吸収する音量判定

スマホやPCでマイク感度がバラバラでも同じように口が動くよう、生の音量ではなく DynamicsCompressor で平準化した信号を判定に使用。実機で繰り返し試し、感度・底上げ量を調整して「反応しない／過敏すぎる」を解消しました。

Web Audio API端末非依存実機チューニング
⚡

フレームワークを使わない軽量PWA

起動の速さとオフライン動作を優先し、バニラJS + Service Worker で構築。ライブラリ依存ゼロで、設定はIndexedDBに保存。ネットが不安定な配信現場でも即起動します。

Vanilla JSService WorkerIndexedDB
▦

ブラウザ内で映像合成＆録画まで完結

Canvasでキャラクターを描画し、クロマキー（指定色の透過）をピクセル処理で実装。iOSの画面収録が使えない場面に備え、アプリ内録画（MediaRecorder）も自前で用意しました。

Canvas 2Dchroma-keyMediaRecorder
◈

使う現場に合わせた連携設計

URLパラメータ ?obs=1 でUIを隠しキャラのみ全画面表示、マイク自動開始。OBS・iPhone画面収録の実運用で詰まる点まで手順化し、CapacitorでAndroid版も同一コードから展開しました。

05

Claude Code との開発プロセス

AIコーディングを活用しつつ、「何を作るか・どこを妥協しないか」の判断は自分で担いました。丸投げではなく、AIを相棒に設計と検証を回した進め方です。

AIAIに任せた部分

  • 要件を機能単位に分解して指示し、実装の下書きを高速に生成
  • Web Audio・Canvasなど不慣れなAPIの叩き方を調べながら実装
  • UIの組み立てや繰り返しの多いコードの量産

ME自分で判断した部分

  • 「音量だけで口パク」という機能を絞る設計判断
  • 音量のしきい値・感度を実機で検証して決定（AIでは詰めきれない体感の部分）
  • 実際に使う知人のフィードバックを受けた改善の優先順位づけ
